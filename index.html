## Run & Operate - pnpm --filter @workspace/api-server run dev — run the API server (port 8080) - pnpm run typecheck — full typecheck across all packages - pnpm run typecheck:libs — rebuild lib declarations (run after changing lib/db schema) - pnpm --filter @workspace/api-spec run codegen — regenerate API hooks and Zod schemas from the OpenAPI spec - pnpm --filter @workspace/db run push — push DB schema changes (dev only) - Required env: DATABASE_URL — Postgres connection string - Optional env: JWT_SECRET — secret for signing JWTs (has a dev fallback) ## Stack - pnpm workspaces, Node.js 24, TypeScript 5.9 - API: Express 5 - DB: PostgreSQL + Drizzle ORM - Auth: JWT (jsonwebtoken) + bcryptjs - File uploads: multer → stored in /uploads/, served at /api/uploads/ - Validation: Zod (v3), drizzle-zod - API codegen: Orval (from OpenAPI spec) — only covers games/categories/chat routes - Build: esbuild (CJS bundle) ## Where things live - lib/db/src/schema/ — all DB tables (games, chat, users, posts, comments) - artifacts/api-server/src/routes/ — API routes (auth, posts, games, categories, chat) - artifacts/api-server/src/lib/auth.ts — JWT middleware - artifacts/api-server/src/lib/upload.ts — multer config - artifacts/game-portal/src/contexts/auth.tsx — global auth state (AuthProvider/useAuth) - artifacts/game-portal/src/hooks/use-api.ts — custom react-query hooks for posts/comments/users - artifacts/game-portal/src/pages/ — feed, login, register, profile, upload, games, categories - uploads/ — uploaded media files (ephemeral in dev) ## Architecture decisions - Auth is JWT-based, tokens stored in localStorage (30-day expiry, no refresh token) - New endpoints (auth, posts, comments) are called directly via fetch + react-query rather than going through the OpenAPI codegen pipeline — keeps the codegen scope focused on games/categories - File uploads stored to disk at /uploads/ and served statically by the API server at /api/uploads/ - bcryptjs (pure JS) used instead of bcrypt to avoid native module build approval requirement - Games/categories/chat routes still use the Orval-generated hooks; new social features use use-api.ts ## Product - **Community Feed** (home): photo/video posts from all users with inline comments - **User Accounts**: register with username/email/password, change username and bio, upload a profile picture - **Profiles**: per-user page showing all their posts - **Upload**: drag-and-drop or browse to upload a photo or video with an optional caption - **Comments**: expandable per-post comment threads, with add/delete support - **Games**: browsable section of embedded open-source games (not the main focus) - **Live Chat**: floating real-time chat widget (username tied to localStorage) ## Gotchas - After changing lib/db schema, run pnpm run typecheck:libs before running api-server typecheck — otherwise the compiled type declarations won't include the new tables - uploads/ is local to the container; files are lost on restart in production. Use object storage for persistent uploads - The OpenAPI spec / codegen only covers games, categories, and chat. New social API endpoints are NOT in the spec — don't regenerate expecting them to appear
